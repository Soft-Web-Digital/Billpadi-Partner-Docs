Authentication & signing

Four layers of enterprise defense: network-level IP whitelisting, an API key for route authorization, cryptographic HMAC-SHA256 signature verification, and dynamic KYC tier & document scope gating.

Layer 1 — IP whitelisting

Billpadi enforces network-level origin IP authorization. You can configure your servers' static IPv4, IPv6, or CIDR blocks via PUT /partner/ip-whitelist or your partner portal. When configured, incoming requests originating from any IP outside your whitelist are dropped with 403 Forbidden (AUTHORIZATION_ERROR).

Layer 2 — API key authorization

Provide your live API key in the x-api-key header of every request:

HeaderValueApplies to
x-api-keysk_live_… (from POST /partner/api-keys)All endpoints under /api/v1/partner/*

This header authorizes read endpoints (catalogs, service providers, rate feeds, transaction queries). If missing, invalid, or belonging to an inactive partner account, the API immediately responds with 401 Unauthorized.

Layer 3 — HMAC-SHA256 request signing

Any action that creates a transaction, debits your wallet, executes a payout, or validates sensitive identity info requires two additional security headers:

HeaderValueDescription
x-timestampUnix epoch milliseconds (e.g. 1752136800000)Prevents replay attacks within a 5-minute tolerance window
x-signatureHex-encoded HMAC-SHA256 digestVerifies payload integrity using your apiSecret

Computing the signature

  1. Serialize the raw JSON body you are transmitting. For requests without a body (or empty payloads), use an empty string "".
  2. Construct the raw message string: {timestamp}.{rawBody} (the timestamp string, followed by a literal period ., followed by the exact raw body string).
  3. Generate the HMAC digest using SHA-256 with your apiSecret as the key.
  4. Encode the digest as a lowercase hexadecimal string and transmit it as x-signature.

Sign the exact JSON string transmitted across the wire. If your client library re-serializes or re-orders JSON keys after signing, the signature verification will fail.

const crypto = require("crypto");

function signRequest(apiSecret, timestamp, rawBody) {
  const message = `${timestamp}.${rawBody}`;
  return crypto.createHmac("sha256", apiSecret).update(message).digest("hex");
}

Timestamp validity window

The x-timestamp header must be within 5 minutes (300,000 ms) of server time. Requests with timestamps outside this range are rejected with 401 Request expired. Ensure your server time is continuously synchronized with standard NTP time servers.

Idempotency & partner references

Every transaction write endpoint requires a unique partnerReference string (2 to 100 characters). This ensures safe retries and prevents double charges if network interruptions occur between your servers and ours.

Layer 4 — Dynamic KYC Tier & Scope Gating

Every partner request is dynamically evaluated against your account's live scope permissions and approved compliance documents. Default baseline policies are summarized below:

Scope Baseline KYC Tier Standard Documents Permitted Actions
catalog Tier 1 None Public listings (networks, DISCOs, packages, rates)
airtime, data, electricity, cabletv, betting, education Tier 2 None (Requires verified BVN or NIN) Utility and bill payments
giftcards Tier 2 None (Requires verified BVN or NIN) Gift card purchase and sale
payouts Tier 2 None (Requires verified BVN or NIN) Bank transfers and wallet withdrawals
crypto Tier 3 Government ID, Proof of Address, CAC Certificate Crypto Buy and Sell orders
kyc Tier 3 Government ID, Proof of Address, CAC Certificate Customer NIN and BVN identity verification APIs

If an endpoint is called before fulfilling the required tier or submitting the required documents, the API responds with 403 Forbidden and machine-readable error code KYC_REQUIREMENT_UNMET detailing the missing requirements.

Dynamic Authorization & Single Source of Truth: Scope mappings and compliance requirements are configured dynamically on the platform. Inspect your live status, active tier, and any pending requirements directly in the web app under Settings → Developer & API, or fetch them programmatically via GET /partner/scopes.
